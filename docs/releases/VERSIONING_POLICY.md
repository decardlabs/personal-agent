# Versioning Policy

## Scheme

This project uses Semantic Versioning: MAJOR.MINOR.PATCH.

- MAJOR: incompatible changes
- MINOR: backward-compatible features
- PATCH: backward-compatible fixes

## Rules

1. Keep VERSION file as single source of current project version.
2. Update CHANGELOG before tagging a release.
3. Create release notes for every released version.
4. Do not release without passing defined quality checks.

## Pre-release Labels

Use labels when needed:

- alpha
- beta
- rc

Example: 0.2.0-beta.1
